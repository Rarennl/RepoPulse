# Repo Health Score 1.0.0

> Обновление интеграций v2: [актуальные изменения, установка и ограничения](../UPDATE.md). Разделы ниже описывают исходную поставку v1; утверждения об отсутствии общего каталога и Security API заменены документом обновления. Исторические проверки и отчёты v1 сохранены.


Методика детерминирована для сохранённых нормализованных входов и времени анализа `analyzed_at`. Это эвристическая оценка сопровождаемости, не сертификация безопасности. Реализация: `app/scoring.py`; правила нормализации: `app/collector.py`, `app/adapters/git_metrics.py`.

## Формула

Базовые веса: Docs 15, CI/CD 15, Security 20, Activity 15, Issues 15, Code health 20; сумма 100. Для метрики j категории i заданы локальный вес aᵢⱼ и балл sᵢⱼ в диапазоне 0–100.

- `Cᵢ = Σ(aᵢⱼ × sᵢⱼ) / Σ aᵢⱼ` только по доступным метрикам.
- `S = Σ(wᵢ × Cᵢ) / Σ wᵢ` только по категориям хотя бы с одной доступной метрикой.
- Если знаменатель равен нулю, результат `null`, отображение «Нет данных».
- Покрытие: `Q = Σ[wᵢ × (Σ доступных aᵢⱼ / 100)]`. Q в процентах.
- Расчёт итогового Score использует неокруглённые категории. Отображение округляется до 0,1, Decimal ROUND_HALF_UP.

В JSON сохраняются нормализованные входы, их SHA-256, timestamp, версия методики, факты, рекомендации и диагностика. `scripts/reproduce.py` воспроизводит формулу без сети. Это воспроизводит **расчёт**, но не обещает восстановить удалённый исходный код по метрикам. Для независимой повторной проверки Git используется сохранённый SHA; для API — дата наблюдения и идентификаторы сущностей. API SourceCraft не даёт атомарный snapshot всех ресурсов: изменения во время обхода возможны.

## Метрики и нормализация

`clip(x) = max(0,min(100,x))`. Даты вычисляются в UTC относительно единого времени начала анализа.

### Документация, вес 15

| Метрика | Локальный вес | Значение и балл |
|---|---:|---|
| README | 25 | При Git-доступе: текст ≥100 символов после strip → 100, иначе 0. При доступе только к дереву — наличие файла → 100, с явным примечанием «содержимое не проверено» |
| LICENSE / LICENCE / COPYING | 20 | Наличие файла в корне, с расширением или без → 100, отсутствие в полном дереве → 0 |
| Инструкция запуска | 20 | В README найдены `install`, `quick.?start`, `запуск`, `установ` (без учёта регистра) → 100, иначе 0 |
| Сборка/тесты | 20 | В README найдены `test`, `build`, `тест`, `сборк` → 100, иначе 0 |
| CONTRIBUTING | 10 | Наличие в корне → 100, отсутствие → 0 |
| CODEOWNERS | 5 | Корень или `.sourcecraft/` → 100, отсутствие → 0 |

Команды из README не выполняются. Лицензия не интерпретируется юридически. Структура фиксируется числом файлов дерева; универсальная «правильная структура» не навязывается. Текстовые эвристики можно обмануть; вклад CODEOWNERS ограничен 0,75 балла итогового полного Score.

### CI/CD, вес 15

| Метрика | Вес | Нормализация |
|---|---:|---|
| Конфигурация | 20 | `.sourcecraft/ci.yaml` или `.sourcecraft/ci.yml` → 100, доказанное отсутствие → 0 |
| Успешность | 60 | `100 × successes / completed` |
| Стабильность | 20 | `100 × (1 − max(0, success_old − success_new))` |

Обход постраничный; выбираются последние 100 по `finished_at` в окне 90 дней. Завершённые: success, failed, timeout; canceled, skipped, rejected, текущие запуски не входят в знаменатель. Для стабильности нужны минимум 10 запусков: новая половина floor(n/2), старая — оставшиеся. Медианная длительность — справочно, не в Score: универсальная «хорошая длительность» для всех стеков некорректна. Нет завершённых запусков ≠ нулевая успешность.

### Security, вес 20

SAST 40, SCA 35, secret scanning 25. Только источник `SourceCraft AppSec`, завершённое и полное сканирование не старше 30 дней, не из будущего. Нет результата / статус pending / неполный охват / неизвестная критичность → `null`.

Для каждого вида: `clip(100 − 60×critical − 25×high − 8×medium − 2×low)`. Уникальность по ID finding. Fixed, resolved, false_positive исключаются; accepted risk не считается исправлением. Info имеет вес 0. Пустой список findings даёт 100 только при подтверждённом полном завершённом сканировании.

**Текущая интеграция:** в зафиксированной официальной Swagger нет метода получения AppSec. Адаптер возвращает unavailable, никаких синтетических результатов не создаётся. Функция нормализации протестирована на явно синтетических unit fixtures, но live Security пока не реализована. Не следует считать этот пункт принятым.

### Активность, вес 15

| Метрика | Вес | Нормализация |
|---|---:|---|
| Активные недели | 55 | `min(100, 100×weeks/8)` |
| Давность | 35 | `clip(100×(1−(days−14)/166))`; нет содержательных коммитов в 90-дневном окне → 0 |
| Авторы | 10 | `min(100,100×authors/3)` |

Окно Git 90 дней, корзины недель `floor((analysis_time−commit_time)/604800)`. Содержательный коммит имеет хотя бы одну запись `--numstat`; пустые коммиты не учитываются. Один коммит в неделю и тысяча коммитов в ту же неделю дают одинаковый вклад недель. Авторы определяются по Git email только в памяти и не сохраняются. Боты, переписанные даты, смена email, массовые форматирования остаются ограничением. Числа MR и релизов / динамика последних 90 дней — справочно, без поощрения искусственных релизов. Для старых стабильных проектов низкая Activity не означает плохое качество кода.

### Issues, вес 15

| Метрика | Вес | Нормализация |
|---|---:|---|
| Медиана первого ответа, часы | 45 | `clip(100×(1−median_hours/168))` |
| Медиана закрытия, дни | 30 | `clip(100×(1−median_days/90))` |
| Доля зависших открытых | 25 | `100×(1−stale/open)` |

Первый ответ — первый комментарий другого пользователя, не раньше создания issue. Без ответа используется текущий возраст (правое цензурирование явно указано). Первые ответы и зависимости обходятся полностью только для ≤100 задач; при большем количестве соответствующая метрика отсутствует, выборка не выдаётся за полную. Закрыты status_type completed/cancelled. Срок закрытия по completed_at − created_at. Зависшие: открытые, без обновления >90 дней. Нет задач / нет закрытых / нет открытых → соответствующая метрика отсутствует. Доля `blocked_by`, открыто/закрыто, создано/закрыто за 30 дней справочные. Приватные issues публичных репозиториев исключены из публичного отчёта.

### Состояние кода, вес 20

| Метрика | Вес | Нормализация |
|---|---:|---|
| TODO/FIXME на 1000 строк | 45 | `clip(100−10×density)` |
| TODO/FIXME старше 180 дней | 35 | `100×(1−old/total)` |
| Файлы >1000 строк | 20 | `100×(1−large/files)` |

Расширения исходников и исключаемые каталоги заданы в `git_metrics.py`, фиксированы версией методики. Учитывается число строк, содержащих TODO/FIXME; текст комментария не сохраняется. Это прокси, способный совпадать с маркерами в строковых литералах; отсутствие TODO не доказывает отсутствие долга. Возраст по `git blame --line-porcelain`, без эвристики переносов; ≤50 файлов с TODO, иначе возраст неизвестен. В полностью обработанном коде без TODO доля старых TODO равна 0 и даёт 100. Нет исходников → нет оценки Code.

## Отсутствие данных и рейтинг

Ошибка доступа/сети/лимита не превращается в отсутствие файла или нулевую частоту. Существование файла проверяется только при полном успешном обходе дерева. Доказанное отсутствие — реальный отрицательный факт. Пропуск содержит причину.

Для основного рейтинга необходимы Q≥80%, все три метрики Security и возраст отчёта ≤8 суток. Иначе результат предварительный и доступен отдельным фильтром; его числовое значение не изменяется штрафом. Это предотвращает лидерство по одному README при недоступных остальных категориях. При текущем отсутствии AppSec основной рейтинг закономерно пуст; включите предварительные оценки для просмотра доступных анализов.

Лайки вообще не входят в Score. Сортировка по лайкам — альтернативный режим представления, не изменение рейтинговой формулы. Равные показатели разрешаются лексикографически по slug. У всех публичных показов проверяется актуальная видимость SourceCraft.

## Рекомендации

Правило срабатывает при метрике <80 и наличии факта. Показываются проблема, важность, действие, факты, категория, приоритет и верхняя граница влияния.

`ΔC = (100−s)×a / Σ доступных a`, `ΔS = ΔC×w / Σ доступных w`.

P0: Security≤20; иначе P1 при ΔS≥5; P2 при ΔS≥2; P3 иначе. Сортировка приоритет, ΔS по убыванию, ID. Δ — контрфактическая верхняя оценка при изменении одной метрики до 100 с неизменными остальными входами; не обещание результата действий. Эффекты нескольких рекомендаций нельзя слепо складывать при изменившемся покрытии.
