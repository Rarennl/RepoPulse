# Обновление: общий каталог, Security API и отображение репозиториев

Это обновление существующего проекта. PostgreSQL, его пароль, токены, ключ шифрования и volumes сохраняются. `.env` в архив не включён; ваш `.env` нельзя заменять примером.

## Установка поверх текущего проекта

Распакуйте архив в отдельную папку. Скопируйте содержимое `repo-health/` из архива в текущую папку проекта с заменой исходников. Сохраните текущий `.env`; БД и Redis остаются в прежнем Compose-проекте. Не меняйте имя каталога проекта и не запускайте второй Compose из папки с другим именем: он создаст отдельные volumes.

Из текущей папки с рабочим `compose.yaml` выполните:

```bash
docker compose up -d --build --force-recreate api worker scheduler
```

Существующую БД пересоздавать не нужно. Очередь, история и PAT остаются. Новый scheduler использует отдельный ключ discovery v2: не нужно удалять lock или очищать Redis. На следующем цикле старые результаты старше часа будут поставлены на пересчёт с AppSec.

Откройте `http://localhost:8000`. Альтернатива без JavaScript: `http://localhost:8000/catalog`. Для проверки сборки откройте `http://localhost:8000/assets/repo-health-v2.js` — должен возвращаться JavaScript, а не HTML. В консоли страницы версия доступна как `window.RepoHealth.version`; глобальной функции `loadRank` в v2 нет, используется `window.RepoHealth.loadRank()`.

## Настройки

Новые поля необязательны: указанные значения уже являются значениями по умолчанию. Добавьте их в существующий `.env`, не меняя рабочие пароли и ключи:

```dotenv
DISCOVERY_MODE=all
APPSEC_ENABLED=true
APPSEC_TOKEN=
APPSEC_AUTH_SCHEME=Bearer
```

- `DISCOVERY_MODE=all`: GET https://api.sourcecraft.tech/repos, все страницы, порядок `created_at`. SOURCECRAFT_ORGS в этом режиме не ограничивает каталог. `organizations` возвращает прежний режим по организациям.
- Без APPSEC_TOKEN публичный сбор пробует текущий SOURCECRAFT_TOKEN. Заголовок по умолчанию Authorization: Bearer. Спецификация Security API не описывает аутентификацию; поддержку такого токена/схемы нужно подтвердить у владельца API. 401/403 отображаются как недоступность, не «0 уязвимостей».
- APPSEC_TOKEN, если задан, применяется только к публичному сбору. Пользовательские анализы используют исключительно собственный PAT пользователя, без подстановки общего токена.
- Базовый адрес Security фиксирован: https://appsec.sourcecraft.tech. Заголовок не пересылается на другие hosts и по redirects.

## Что изменилось

1. DiscoverRepositories: 100 элементов/страница, максимум 10 страниц за цикл scheduler, cursor сохраняется. Следующий цикл через 5 минут продолжает обход, повтор полного обхода — через сутки после завершения. Каждый найденный публичный repo сразу добавляется в SQL и очередь, повторные записи идемпотентны. API исключает private organizations/projects; изменение видимости всё ещё может менять страницы, поэтому нет гарантии атомарного полного snapshot.
2. AppSec: GET `/v1/scans/latest`, GET `/v1/scans/{scanUuid}`, GET `/v1/defect-groups`. `gitRepo` — UUID/числовой ID из Repository.id, не slug. JSON-контракт сохранён в `contracts/appsec.openapi.json`.
3. Список показывает предварительные оценки по умолчанию. Чтобы видеть только допущенных в рейтинг, снимите флажок. Правила допуска и сама формула Score не ослаблены.
4. JavaScript обслуживается отдельным версионированным маршрутом с явным MIME type. Инициализация изолирована от глобальных переменных. Авторизация загружается независимо от публичного каталога. Вместо вечного прочерка видны loading/error и ссылка на серверный каталог.

## Как интерпретируется Security

Подробности scan имеют строковый FINISHED, в отличие от числового статуса summary. Для дефектов числовые severity/status не расшифровываются по позиции enum. Серверные фильтры `type`, повторяемые `severity` и `status` задают классификацию. Сравниваются множества UUID групп между запросами; неполные страницы, изменившийся totalSize, неизвестная классификация и конфликт severity дают missing.

Единица штрафа — группа дефектов (UUID), а не каждое повторение finding. Сохраняются только ID/номер/критичность риска и ссылка на репозиторий. `codeBlock` и другие исходные фрагменты не попадают в БД, cache и лог.

Риск-статусы: OPEN, TRIAGE_IN_PROGRESS, TRIAGED_TP, FIX_IN_PROGRESS, RESOLVED_TOLERABLE. RESOLVED_FIXED, RESOLVED_AUTOFIXED, RESOLVED_FP, RESOLVED_PROJECT_NOT_AFFECTED, RESOLVED_DUPLICATE исключаются. Критичности NONE/LOW/MEDIUM/HIGH/CRITICAL; NONE соответствует info, штраф 0.

Нужен завершённый запуск не старше 30 дней. Для каждого из SAST/SCA/SECRETS требуется хотя бы одна связанная со scan группа как свидетельство данных данного движка. Пустая выдача сама по себе не доказывает запуск движка: такой результат — missing, а не 100. Поэтому чистый repo без групп может остаться предварительным до появления в контракте явного per-engine coverage. По завершённому scan оценивается доступный набор групп, не утверждается полнота покрытия всего исходного кода. Даты integer проверяются как однозначный разумный Unix timestamp в секундах/миллисекундах; единицы в draft явно не указаны.

## Проверки

41 Python-тест пройден: discovery pagination/deduplication, AppSec numeric enums через фильтры, 403, FAILED, неполные страницы, пустой движок, MIME, fallback, прежние ACL/очередь/scoring. Проверена видимость предварительных результатов по умолчанию и в серверном каталоге. Контрактная проверка: 9 методов платформы и 3 Security. DOM-интеграция: 50 строк, обновление, зависшая авторизация не блокирует список, ошибка сети видна. Это jsdom, не визуальная проверка Firefox. Установка Chromium в среде проверки недоступна из-за сетевых ошибок.

Swagger обоих сервисов получен live; неавторизованный запрос AppSec вернул 401. Токена пользователя в среде разработки нет, поэтому успешный авторизованный AppSec-запрос здесь не подтверждён. После обновления смотрите `diagnostics.appsec` в детализации репозитория и журналы:

```bash
docker compose logs --tail=80 scheduler worker
curl 'http://localhost:8000/api/leaderboard?partial=true'
```

Если AppSec отклоняет токен, каталог всё равно отображается, остальные метрики и отчёты продолжают работать. Приложенные Git-only отчёты из предыдущей версии остаются историческими и не выдаются за новые полные security-отчёты.
